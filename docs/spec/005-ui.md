# 005 — UI

Compose, one Activity, not XML Views, not a WebView of the site.

## 0.1.0 screens

| Destination | Content |
|---|---|
| Now Playing | Play/stop, volume 0–100 (default 80), title/artist, collapsible tags, progress + mm:ss / mm:ss (AFK only; live DJ has no track clock), listeners, DJ image + `dj.djname`, thread link if present, **next** track then **previous** track |
| Songs | Section tabs **Last Played** \| **Queue**; Queue section hidden entirely when not AFK; `/r/` + blue on `type == 1` |
| Settings | Section tabs **General** \| **Auto**. General: auto-start on plug, about (r/a/dio, Geiravor, based on r/a/dio's Valkyrie, version). Auto: auto-start in vehicle |

## 0.2.0 screens

| Destination | Content |
|---|---|
| Now Playing | 0.1.0 chrome plus **Fave** (verb). Heart fill/outline is the success feedback (do not fill on a failed fave, do not unfill on a failed unfave); failures only as red text, faded out when `np` changes |
| Songs | Section tabs **Last Played \| Queue \| Request \| Favorites**. Queue hidden when not AFK. Request is search + request. Favorites is nick + public list + per-row Request when AFK + **Request random** (`006-requests-faves.md`) |
| News | List + article (`007-news.md`) |
| Settings | Section tabs **General \| Auto \| Connection**. Overflow **Alerts** (alarm / snooze / sleep / DJ notifier) — not a fifth bottom tab. Connection is Rizon vs Bouncer IRC (`006-requests-faves.md`, `008-settings.md`): password and client-key fields are masked with no copy/cut; client cert may copy; Clear+confirm on each PEM; Test connection shows the server SHA-256 |

Phone: **bottom tabs** **Now Playing \| Songs \| News \| Settings** (Settings last). Two-pane only when **width ≥ 840dp and smallest width ≥ 600dp** (tablet / wide). 16:9 phones stay single-pane in landscape.

If **Now Playing** / **Last Played** do not fit one line: **two-line labels**, no hardcoded character cap. Tabs (and their icons/labels) are **vertically centered** so **Songs** sits at mid-height of **Now Playing**.

UI noun is **Favorites**. Verb / Auto command is **Fave**. Do not label anything **Faves**.

Two-pane: **Now Playing is always the left pane.** Bottom tabs are **Songs \| News \| Settings** and switch only the right pane (default Songs). There is no Now Playing tab when the left pane is already showing it. Thread stays phone-only (not the tablet pane).

Songs and Settings use **section tabs** at every width.

## Layout

Follow the live homepage order for player chrome: play + volume, title, tags (+/-), progress + listeners + clock, DJ column.

Now Playing lists the **next** song first (`queue[0]` when AFK; live DJ: `???`) and the **previous** song second (`lp[0]`). Currently playing may wrap up to two lines. Next and previous are one line each, ellipsized to the width of the screen. DJ name is centered under the image. Full last-played and queue live on the Songs tab.

Tags: one space-separated line from `tags[]`, collapsed behind +/- like the site.

Times: relative from `timestamp` vs `current` (`002-api.md`).

Thread: phone only.

## Theme: live `default-dark`

Not the old app’s orange `#DF4C3A`. Tokens from `/assets/default-dark/css/bulma.min.css`:

| Token | Live | Use |
|---|---|---|
| `--radio-secondary-1` | hsl(0, 0%, 11%) | screen background |
| `--radio-primary-1` | hsl(0, 0%, 13%) | cards / bars |
| `--radio-primary-3` | hsl(0, 0%, 24%) | borders / raised |
| `--text-secondary` | hsl(0, 0%, 96%) | primary text |
| `--text-primary` | hsl(0, 0%, 50%) | muted text |
| `--blue` | hsl(208, 27%, 39%) | play / request / links |
| `--red` | hsl(348, 27%, 50%) | errors |
| `--green` | hsl(153, 27%, 39%) | success |
| `--text-link` | hsl(208, 27%, 50%) | links |

Play control uses the blue (`is-info` equivalent). Material 3 is re-skinned to these tokens.

Light and holiday/DJ CSS themes are later (`000-product.md`).
